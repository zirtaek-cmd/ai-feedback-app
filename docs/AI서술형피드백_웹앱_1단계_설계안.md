# AI 서술형 피드백 웹앱 — 1단계 설계안 (배치 방식 / 완전 무료)

> 목적: 중3 과학 학습지 서술형 답안을 학생이 웹에서 사진으로 제출하면, AI가 채점·피드백하고, 교사 검토 후 학생이 자기 방에서 확인·복습하는 통합 웹앱.
> 원칙: 카드 등록 없이 100% 무료(Firebase Spark + Gemini 무료 등급), 채점은 교사가 Claude Code로 실행하는 배치 방식.

---

## 1. 전체 구조

```
[학생 브라우저] ──제출(이미지)──▶ [Firestore] ◀──읽기/쓰기── [Claude Code (교사 PC)]
       ▲                             │  ▲                          │
       │                        승인된 결과만              Gemini 무료등급 채점
       └────자기 방에서 확인────────┘  └────채점 초안 되쓰기──────────┘

[교사 브라우저] ──검토·수정·공개──▶ [Firestore]
```

- **웹앱**: 학생 제출/열람 + 교사 검토/공개. Firebase Hosting(또는 GitHub Pages)에 배포.
- **Claude Code(교사 PC)**: 채점 엔진 전용. 교사가 명령으로 실행 → 밀린 제출물을 Gemini로 채점 → 초안을 Firestore에 기록.
- **Firestore**: 학생 웹과 Claude Code가 공유하는 단일 저장소. 이미지·점수·피드백 전부 여기 누적.

역할 분리 요약: **제출·검토·공개·열람 = 웹앱**, **채점 = Claude Code**. 서버(Cloud Functions)와 Cloud Storage를 쓰지 않으므로 카드가 필요 없음.

---

## 2. 사용 서비스 (전부 무료 Spark 플랜)

| 기능 | 서비스 | 비고 |
|---|---|---|
| 로그인 | Firebase Authentication (Google) | 학교 도메인 제한 + 등록 명단만 입장 |
| 데이터·이미지 저장 | Cloud Firestore | 이미지는 압축 후 base64로 보관 |
| 웹 호스팅 | Firebase Hosting | GitHub Pages도 가능 |
| 채점 실행 | Claude Code + Gemini API | 교사 PC 로컬, 무료 등급 키 |
| 관리자 접근 | Firebase Admin SDK (서비스 계정) | Claude Code가 전체 접근 |

예상 비용: **0원**. (학습지 6개 × 100명 ≈ 최대 600장, 압축 시 약 180MB로 Firestore 무료 1GB 이내.)

## 3. 화면 설계

### 3-1. 로그인 화면
- "구글로 로그인" 버튼 하나.
- 로그인 후 이메일이 **등록 명단(roster)** 에 있는지 확인 → 없으면 입장 차단 안내.

### 3-2. 학생 개인 화면 (와이어프레임 반영)

```
┌──────────────┬───────────────────────────────────────────────┐
│ [사이드바]    │  4-1-1 학습지                       [상태 배지] │
│              │                                                │
│ ▸ 4단원       │  ┌───────────────────┐   ┌──────────────────┐ │
│   4-1-1 ✅    │  │ 업로드한 과제 이미지 │   │  [업로드 창]      │ │
│   4-1-2 ⏳    │  │  (클릭 시 확대)     │   │  사진 선택/촬영    │ │
│   ...        │  └───────────────────┘   │  → 제출 버튼       │ │
│ ─────        │  ┌───────────────────┐   └──────────────────┘ │
│ ▸ 5단원       │  │ 채점 및 피드백       │                       │
│   5-1-1 ✅    │  │ 총점 / 항목별 점수   │                       │
│   ...        │  │ 피드백 내용          │                       │
│              │  └───────────────────┘                        │
└──────────────┴───────────────────────────────────────────────┘
```

- **왼쪽 사이드바**: 단원 → 학습지 목록(누적). 각 학습지 옆에 상태 표시
  - `미제출` / `⏳ 채점 대기·검토 중` / `✅ 완료(피드백 열람 가능)`
- **가운데·오른쪽 전체 배치는 가시성 위주로 구성** (아래는 예시 배치):
  - 선택한 학습지가 **미제출**이면 → 업로드 창(사진 선택/촬영, 여러 장 가능)이 크게 표시, 제출 버튼.
  - **제출 후~공개 전**이면 → 업로드한 이미지 표시 + "채점 검토 중" 안내(점수·피드백은 아직 안 보임).
  - **공개 후**면 → 위: 업로드 이미지(클릭 확대), 아래: 채점·피드백 카드(총점 + 항목별 점수 + 피드백).
- **복습 동선**: 과거 학습지를 사이드바에서 눌러 사진·점수·피드백을 다시 열람 → 시험공부 활용.

### 3-3. 교사 화면 (관리자 로그인)
- **검토 대기 목록**: 채점 완료(초안) 상태의 제출물. **"확인 필요" 플래그가 붙은 건을 맨 위로** 정렬.
- **개별 검토**: 학생 이미지 + AI 초안(총점·항목별·피드백)을 나란히 보고, 점수·피드백 수정.
- **공개**: 개별 또는 일괄 "공개" → 그때부터 학생 방에 표시.

## 4. 데이터 구조 (Firestore)

```
roster/{email}
  - name, class(반), number(번호)          # 등록 학생 명단. 없으면 입장 불가

worksheets/{worksheetId}                    # 예: "4-1-1" (사이드바 정리용 슬롯)
  - unit(단원), code, title, order
  - active(bool)
  # 문제 내용은 저장하지 않음 — 제출 이미지에서 Gemini가 문제·답안을 함께 읽음

submissions/{submissionId}                  # (학생 × 학습지 × 회차)
  - studentUid, studentEmail, worksheetId
  - status: "submitted" | "graded" | "released"
  - attempt(int)
  - submittedAt, gradedAt, releasedAt
  - grade { total, concept, logic, evidence, expression }   # ← 공개 시에만 기록
  - feedback (string)                                       # ← 공개 시에만 기록

submissions/{submissionId}/pages/{pageId}   # 이미지 1장 = 1문서 (1MiB 한도 회피)
  - imageBase64 (압축 300~500KB), order

reviews/{submissionId}                       # 교사 전용. AI 채점 초안 보관
  - grade{...}, feedback, reviewFlag(bool), reviewReason
  - (관리자만 접근. 공개 시 확정본이 submissions로 복사됨)
```

**핵심 설계 포인트 — 공개 전 점수 은닉**: AI 채점 초안은 학생이 못 읽는 `reviews/`에 저장. 교사가 "공개"하면 그때 확정 점수·피드백이 학생이 읽을 수 있는 `submissions/` 문서로 복사되고 `status="released"`가 됨. 화면에서 가리는 게 아니라 **데이터 접근 자체를 차단**.

---

## 5. 보안 규칙 (Firestore Security Rules)

- `roster/{email}` — 본인(로그인 이메일 일치)만 읽기, 쓰기는 관리자만.
- `worksheets/{id}` — 로그인+명단 등록된 학생 읽기, 쓰기 관리자만.
- `submissions/{id}` — **본인(studentUid 일치) 것만** 생성·읽기. 수정·삭제는 관리자만.
- `submissions/{id}/pages/{pageId}` — 본인 것만 생성·읽기.
- `reviews/{id}` — **관리자만** (학생 접근 전면 차단).
- 관리자 식별: 교사 계정에 `admin` 커스텀 클레임 부여(최초 1회 Admin SDK로 설정).
- Claude Code는 **서비스 계정 키(Admin SDK)** 로 규칙을 우회해 전체 접근.

## 6. 채점 (Claude Code 배치)

### 실행 방식
교사가 터미널에서 명령 실행 → 밀린 제출물 일괄 채점.
- `submissions` 중 `status="submitted"` 조회 → 각 제출의 pages(이미지) 로드 (문제·답안 모두 이미지에서 Gemini가 읽음)
- Gemini 무료 등급 호출(분당 한도 고려해 천천히 순차 처리) → 구조화 JSON 수신
- 결과를 `reviews/{id}`에 저장, `submissions.status="graded"`로 변경
- 종료 시 요약 출력: "N명 채점 완료, 이 중 M명 확인 필요"

### 채점 기준 (프롬프트에 고정)
| 관점 (중요도 순) | 배점 |
|---|---|
| ① 핵심 개념을 맞게 이해했나 | 40 |
| ② 문장이 논리적으로 이어지나 | 25 |
| ③ 근거·예시를 들었나 | 20 |
| ④ 자기 말로 풀어 설명했나 | 15 |

- 100점 만점. **격려 문구 없이** 내용 중심 피드백(맞은 점 / 빠진 점 / 보완점).
- 손글씨 판독이 애매하면 `reviewFlag=true` + 사유 → 교사 우선 검토.
- 문제·정답은 교사가 제공하지 않음 → Gemini가 이미지에서 **문제를 읽고, 자체 지식 기준으로** 채점·피드백. (기준이 흔들릴 수 있는 부분은 교사 검토 단계에서 보정)

### 채점 출력 스키마 (JSON)
```json
{
  "total": 0,
  "criteria": {
    "concept":    {"score": 0, "note": ""},
    "logic":      {"score": 0, "note": ""},
    "evidence":   {"score": 0, "note": ""},
    "expression": {"score": 0, "note": ""}
  },
  "feedback": "",
  "reviewFlag": false,
  "reviewReason": ""
}
```

## 7. 이미지 압축 (브라우저)

- 제출 전 브라우저에서 리사이즈+압축 → **장당 300~500KB** 목표(글씨 판독 가능 수준).
- base64로 인코딩해 `pages` 서브컬렉션에 1장=1문서로 저장(각 1MiB 미만).

---

## 8. 제작 순서 (1단계 = 핵심 흐름부터)

1. Firebase 프로젝트 셋업(Spark) + 구글 로그인(학교 도메인 제한) + roster 입장 통제
2. 학생 화면: 사이드바(단원·학습지) + 업로드 창 + 제출(이미지 압축·저장)
3. Claude Code 채점 스크립트(Gemini) → `reviews`에 초안 저장
4. 교사 화면: 검토 대기 목록(확인필요 우선) + 수정 + 공개
5. 학생 화면: 공개된 점수·피드백 표시 + 과거 회차 열람(복습)
6. 보안 규칙 적용 + 제출 형식·용량 검증

**2단계(이후, 필요 시)**: 학생 댓글/되묻기, 단원별 취약점 통계, 재제출 관리 고도화 등.

---

## 9. 제작 착수 전 필요한 자료

1. **학습지 목록** — 남은 단원의 학습지 코드 + 제목 (예: `4-1-1 광합성`). 사이드바 슬롯 구성용. **문제 내용은 불필요**(이미지에서 읽음).
2. **학생 구글 계정 목록** (이메일 / 이름 / 반 / 번호)
3. **학교 구글 도메인** (로그인 제한용)
4. **교사 구글 계정** (관리자 지정용)
5. **제출 이미지 샘플 1~2장** — *있으면* 채점 프롬프트 보정용. 없어도 착수 가능, 생기면 추후 제공.

---

## 10. 착수 전 확정할 소수 결정사항

- **학습지 등록 방식**: 1단계에선 학습지 목록(코드+제목)만 제가 시드 등록, 교사용 등록 폼은 2단계. (원하면 1단계에 폼 포함 가능)
- **재제출 허용**: **재제출 2회까지**(최초 제출 포함 최대 3회), 최신본 채점, 회차 이력 보관. → 보안 규칙에서 횟수 제한 강제.
- **여러 장 제출**: 지원(활동지 여러 페이지).
